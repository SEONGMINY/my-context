# 도메인 스토리텔링 워크숍

업무 참여자가 무엇을 보고 판단하고 행동하는지 함께 파악하고, 사용자가 요청한 단계의 산출물로 남긴다. 현재 단계는 [단계별 진행 지침](references/stages.md)에서 확인한다. 문서를 작성할 때 [단계별 빈 양식](templates/workshop-documents.md)의 해당 부분을 대상 프로젝트에 맞게 사용한다. MCP에서 읽을 때는 `chub_get`에 첨부 파일의 상대 경로를 지정한다.

## 시작

- 프로젝트의 목표와 제약, 원문과 기존 해석 자료, 참여자가 업무를 직접 아는 범위, 요청 단계와 기존 산출물을 확인한다.
- AS-IS를 다룰 때는 관찰된 현행 업무를 설명하는지, 주어진 조건에서 업무를 재구성하는지 합의한다. 범위나 산출물, 표현 방식과 완료 기준이 모호하면 인터뷰에 앞서 필요한 것부터 묻는다.
- 기존 산출물이 있으면 유효한 합의와 미결정을 확인하고 요청한 단계에서 시작한다. 이미 답한 질문은 반복하지 않는다.

## 인터뷰

- 전체 업무에서 시작해 필요한 세부 단계로 좁혀간다. 한 번에 핵심 질문 하나를 하고, 답변을 짧게 되짚은 뒤 다음 질문을 고른다.
- 답하기 어렵다면 한 단계나 한 판단으로 좁힌다. 상황이나 선택지에 더한 전제를 밝힌다. 그 전제가 답을 바꿨다면 참여자가 자기 말로 판단을 다시 설명하도록 돕는다.
- 원문이나 직접 경험에서 확인한 사실, 합의한 업무 가설, 해결책 제안, 미확인 사항을 근거와 함께 기록한다. 참여자가 앞선 답을 정정하면 근거와 확인 상태도 갱신한다. 외부 자료는 해당 자료가 뒷받침하는 범위에서 사용한다.
- 현재 단계의 결정이나 산출물이 달라지는 질문을 우선한다. 다음 단계에 필요한 미결정은 남겨두고 현재 논의로 돌아간다.

## 검토와 작성

- 현재 단계의 결과를 사용자와 검토한다. AS-IS는 전체 이야기를 먼저 확인하고, 참여자·활동·업무 대상·순서와 시작·종료 조건을 점검한다.
- 합의한 내용을 대상 프로젝트에 작성한다. 프로젝트의 기존 문서, 파일 경로와 작성 규칙을 따른다. 작성한 문서를 인터뷰와 대조해 중요한 판단 이유, 후속 행동의 순서, 근거와 미확인 사항이 보존됐는지 확인한다.
- 사용자가 요청한 산출물이 완료되면 마친다. 후속 단계가 요청됐으면 합의한 산출물과 미결정을 이어받아 진행한다.
