# 프로덕트 이해

현재 작업 대상 프로젝트가 무엇을 제공하고 어떻게 동작하는지 근거를 확인해 이해한다. 웹·앱·서버·SDK·라이브러리·CLI 등 프로젝트 유형이나 기술 스택에 특정 구조를 전제하지 않는다.

## 적용 범위

- 개발 세션 시작 시 제품 이해를 요청하거나, 사용자가 제품·저장소 이해를 요청할 때 적용한다. 세션 시작 점검으로 두 Skill을 함께 요청받았다면 제품 이해를 먼저 수행하고 확인한 맥락을 문서 검토에 넘긴다.
- 같은 세션에서 확인한 정보가 유효하면 재사용한다. 후속 Task마다 전체 탐색을 반복하지 않고 변경으로 영향을 받은 부분만 다시 확인한다.
- 프로젝트에 맞는 읽기 가능한 자료와 코드가 입력이다. 특정 파일명, Git 호스트, 실행 환경, 문서 작성이나 별도 컨텍스트 파일을 강제하지 않는다.

## 확인 절차

1. **목적과 범위:** 제품 설명, 요구사항, 실제 사용 형태에서 해결하려는 문제, 대상 사용자·소비자, 제공 범위를 파악한다. 문서의 주장과 확인된 구현은 구분한다.
2. **기능과 동작:** 주요 진입점과 핵심 기능의 호출·데이터·상태 흐름을 따라간다. 프로젝트 유형에 맞게 UI 흐름, API 계약, SDK 공개 인터페이스 등을 선택적으로 본다.
3. **구조와 책임:** 주요 모듈, 의존성, 외부 연동, 실행·배포 환경 중 현재 제품을 설명하는 데 중요한 부분을 확인한다. 파일을 모두 순회하지 않고 핵심 경로부터 탐색한다.
4. **현재 상태:** 실제 코드·설정·테스트에서 확인한 사실, 문서상의 의도, 추론과 미확인 사항을 구별한다. 충분히 설명할 수 있으면 탐색을 종료한다.

## 결과와 인계

프로덕트의 목적, 주요 기능·동작, 핵심 구조 및 책임, 확인 근거와 미확인 사항을 요청 규모에 맞게 간결히 설명한다. 복잡한 관계는 도움이 될 때만 다이어그램으로 나타낸다.

동일 세션에서 문서 검토를 이어간다면 확인한 제품 컨텍스트와 근거를 재사용할 수 있게 한다. 요약은 근거를 대체하지 않으며 별도 파일 저장을 요구하지 않는다.

## 경계

- 제품 이해 자체는 문서의 불일치·불필요·누락을 감사하는 작업이 아니다. 그 검토는 별도 요청 또는 documentation-review의 책임이다.
- 이 Skill은 읽기 전용으로 제품의 현재 상태만 파악한다. 개선 계획이나 파일 변경이 필요한 경우 별도의 작업으로 다룬다.
- 접근할 수 없는 파일이나 실제 실행하지 않은 동작은 확인했다고 표현하지 않는다.
- 두 Skill이 세션 시작 시 함께 사용될 수 있지만, 이 Skill이 다른 Skill의 자동 호출이나 세션 시작 감지를 보장하지는 않는다.
