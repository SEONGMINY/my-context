# my-context · 선택적 개인 자산 활용 (사용자가 활성화한 경우)

이 정책을 직접 활성화한 환경에서 관련 개인 지식과 게시된 공통 Skill을 선택적으로 읽고 적용할 수 있다. 로컬에 설치된 Skill의 자동 발견은 사용 동의가 아니며, 현재 작업에서 my-context 활용을 금지하면 같은 저장소가 제공하는 로컬·원격 Skill 모두 자동으로 읽지 않는다. MCP 연결 자체는 동의가 아니다. 기존 개인 원칙 전용 정책은 공통 Skill 자동 활용 동의로 확대하지 않는다. 현재 사용자의 활용 금지와 프로젝트 권한을 우선한다.

1. 목표·산출물·범위·기존 결정을 파악한다. 예시는 확정 요구사항으로 취급하지 않고 정정 시 영향을 받은 판단을 다시 확인한다. 자산 이름 없이 my-context 사용을 요청해도 관련 자산을 발견한다.
2. 현재 판단에 실질적인 도움이 될 때만 `chub_search`로 탐색한다. 작업 목적을 나타내는 최소 키워드를 사용하며 코드·인증정보·고객 데이터·사적 대화 원문은 보내지 않는다. 작은 수정이나 비관련 요청에서는 자동 조회를 생략한다.
3. 후보 설명과 역할 및 적용 조건을 비교한다. 개인 지식은 판단 기준으로, 공통 Skill은 현재 목표에 필요한 절차로 활용한다. 겹치는 절차를 반복하지 않고 별도 명시적 요청을 요구하는 자산은 그 조건을 유지한다. 프로젝트 계약과 사용자 지시를 우선하며 중요한 충돌은 드러낸다.
4. 필요한 진입 파일과 첨부만 `chub_get`으로 읽는다. 개인 원칙을 적용할 때는 knowledge.md 본문을 확인한다. 검색 리비전을 조회에 전달하고 불일치 시 필요한 자산을 다시 발견한다. 이미 읽은 유효한 본문은 재사용한다. 새로운 판단이나 정보 부족이 생기면 추가 탐색하되 충분하거나 새로운 관련 후보가 없으면 종료한다.
5. 조회는 수정·설치·커밋·푸시·배포나 추가 개인 데이터 접근의 허용이 아니다. 지식 변경은 별도 승인과 `manage-dev-knowledge` 절차를 따른다. 자산을 찾지 못하거나 연결이 없으면 조회 성공을 주장하지 않고 가능한 범위에서 진행한다.

모든 작업의 강제 체크리스트나 별도 실행 Workflow가 아니다. 이 정책을 로드했다는 사실은 MCP 연결·조회·적용 성공을 의미하지 않는다.
