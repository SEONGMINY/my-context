# my-context · 자산 사용 경계

AI는 사용자가 `my-context 사용해서 ...`라고 명시적으로 요청한 작업에서 **관련 자산만** 검색·조회·적용한다. 호스트가 자율 선택을 지원한다면 명시적 이름 없이도 관련 자산을 참고할 수 있지만, 이는 모든 환경에서 보장되는 필수 동작이 아니다.

## 적용 경계

1. **현재 사용자 지시 우선:** 사용자가 이번 작업에서 my-context 사용을 금지하면 해당 자산을 조회·적용하지 않는다.
2. **프로젝트 계약 우선:** 해당 프로젝트의 요구사항·규칙·아키텍처 계약이 공통 참고 자산보다 우선한다.
3. **조회와 변경 분리:** MCP 조회는 지식 등록·수정·삭제, Git 변경, 커밋·푸시·배포, 추가 개인 자료 접근을 승인하지 않는다.
4. **계획과 실행 구분:** 계획만 요청했다면 실행하지 않는다. 실행 요청이 이미 있다면 승인 범위 내에서 진행하되 별도 권한이 필요한 행위는 기존 정책을 따른다.

## 필요한 만큼만 조회

검색에는 작업 목적을 설명하는 최소 키워드만 사용한다. `chub_search`로 후보를 찾고 이름·설명·역할을 비교한 뒤, 실제 판단에 필요한 자산만 `chub_get`으로 읽는다. 필요할 때만 첨부를 추가로 조회한다. 단순한 작업이나 이미 유효한 본문이 있는 경우에는 불필요한 전체 목록·중복 조회를 피한다.

비공개 코드, 인증 정보, 고객 데이터, 사적 대화 원문 등 불필요한 민감 정보는 검색어로 전송하지 않는다. 검색·조회 실패나 호스트의 MCP 도구 미노출은 성공으로 주장하지 않는다.

이 문서는 AI의 행동 지침이지 호스트의 도구 호출이나 파일 접근을 기술적으로 강제하는 보안 정책이 아니다. 실행 성공 여부는 실제 도구 호출 기록과 결과물로 검증한다.
