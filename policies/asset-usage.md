# my-context · 선택적 개인 자산 활용 (사용자가 활성화한 경우)

이 지침은 사용자가 자신의 에이전트 환경에서 **개인 자산의 읽기 전용 활용을 직접 활성화했을 때** 적용한다. MCP가 연결됐다는 사실만으로 활성화한 것으로 간주하지 않는다. `development-workflow` 등 특정 Skill의 호출을 전제로 하지 않는다.

1. 요청에서 사용자가 해결하려는 문제, 산출물 수준(요구사항·조사·설계·구현·검증), 범위와 기존 결정을 파악한다. 사용자의 **예시를 확정 요구사항으로 취급하지 않는다**. 정정이 생기면 영향을 받은 추론·계획을 재검토한다.
2. 개인 원칙이나 Playbook이 이번 판단에 **실질적으로 도움될 가능성이 높을 때만** 연결된 `my-context` MCP의 `chub_search`로 관련 자산을 찾는다. 제목뿐 아니라 설명·적용 조건을 비교하고, 필요한 **최소 자산**만 `chub_get`으로 조회한다. 비관련 작업이나 작은 수정에는 조회를 생략한다.
3. 현재 사용자 지시와 대상 프로젝트의 정책·코드·계약을 자산보다 우선한다. 서로 다른 원칙이 충돌하면 차이를 확인하되, 임의로 정책을 바꾸지 않는다. 자산을 찾지 못하거나 MCP가 연결되지 않았다면 조회했다고 주장하지 말고 이용 가능한 맥락에서 작업한다.
4. 개인 지식 **조회 허용은 수정·설치·커밋·푸시·배포 허용이 아니다**. 기존 대화·개인 파일을 추가로 검색할 권한도 아니다. 새로운 인사이트나 불일치를 발견해도 자동 등록하지 않는다. 사용자가 인사이트 도출을 원할 때 후보를 제안하고, 지식 변경은 별도 승인과 `manage-dev-knowledge` 절차에 따른다.
5. 개인 자산의 활용은 모든 작업에서 강제하는 체크리스트나 별도의 실행 Workflow가 아니다. 필요한 요청에서만 근거를 적용하며, 사용자의 최종 목표를 보존한다.

**이 지침을 로드했다는 사실은 MCP 연결이나 특정 원칙의 조회 성공을 의미하지 않는다.** 사용자가 개인 지식 조회를 명시적으로 금지하면 이 지침보다 해당 요청을 우선한다.
