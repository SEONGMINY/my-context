# Execution Strategy — 실행 방식 선택

**판단 원칙:** 작업을 독립적으로 분해할 수 있다는 것과 실제로 병렬 실행하는 것이 유리하다는 것은 별개다.

## 적용 조건

독립 Task가 여러 개 있거나 Sub-agent 위임, 조사·구현의 분리, 세션 간 인계처럼 **실행 방식에 선택지가 있을 때** 적용한다.

## 판단 기준

- 각 Task의 실제 산출물과 수용 조건은 무엇인가? 다른 Task의 *수용된 결과*가 필요한가?
- 단일 Agent, 순차 실행, 전체 병렬, 조사만 병렬 위임 중 무엇이 적합한가?
- 예상 절약 시간보다 컨텍스트 전달, 중복 탐색, 파일 충돌, 통합·재검증 비용이 큰가?
- 공유 상태의 소유자는 누구이며, 차단 사항과 중요한 계약 변경을 누구에게 전달해야 하는가?

**예외:** 독립 Task가 많아도 작거나 같은 파일·계약에 강하게 결합돼 있으면 단일 실행이 나을 수 있다. 병렬 실행의 효율을 실제 측정하지 않았다면 개선을 확정하지 않는다.

**근거 수준:** 사용자가 Task 의존 관계와 맥락 이어짐을 고려한 병렬 Sub-agent 실행을 *제안*하고, 작업 현황의 실시간 공유 필요성까지 *질문*한 과정에서 추출한 후보 원칙이다. 병렬화를 항상 요구한 것은 아니다.
