# Risk Management — 위험 관리

**판단 원칙:** 적절해 보이는 선택이나 계획도 실제로 실패할 수 있다. 중요한 위험의 원인과 영향을 분석하고, 필요한 대응의 효과·비용·실행 가능성과 대응 후 남는 위험을 판단한다.

## 적용 조건과 경계

실행 전 계획 검토, 중요한 설계·데이터·계약 변경, 외부 의존성, 운영 작업과 같이 실패의 피해나 재작업이 의미 있는 상황에서 적용한다. 이미 승인한 계획이라도 새로운 위험이 발견되면 영향을 다시 판단한다. 작은 수정에 전면 위험 분석이나 별도 문서를 강제하지 않는다. 위험 발견은 변경·배포·위험 수용 권한을 부여하지 않는다.

## 위험 발견과 표현

계획이 실패했다고 가정하고 그 이유를 역으로 탐색하거나, 시스템의 상태·입력·경계·상호작용을 검토한다. 아래 관점 중 실제 대상에 관련된 것을 선택한다.

| 관점 | 탐색할 위험 |
| --- | --- |
| 요구·맥락 | 의도 누락, 잘못된 가정, 미결정 정책, 오래된 정보 |
| 설계·계약 | 책임 침범, 호환성, 인터페이스 불일치, 결합도 |
| 데이터 | 유실, 중복, 동시성, 일관성, 마이그레이션, 개인정보 |
| 실행 | 작업 충돌, 의존성 오류, 맥락 손실, 권한 |
| 외부 의존성 | 장애, 공급자 변경, 버전·사용량 제한 |
| 검증 | 결함 누락, 검증 공백, 근거 없는 완료 |
| 운영 | 성능·가용성 저하, 탐지·복구 불가 |
| 유지보수·비용 | 기술 부채, 불일치, 시간·토큰·재작업 증가 |

위험은 원인 또는 조건 → 위험 사건 → 사용자·시스템·계약에 미치는 결과로 구체화한다. 실제 관측과 미래 가설을 구분하고 근거를 확인한다.

**연쇄 위험:** 개별 실패뿐 아니라 여러 정상 동작의 잘못된 상호작용, 공통 원인, 연쇄적 영향까지 고려한다. 예를 들어 맥락 누락 → 불일치 구현 → 통합 실패 → 일정 지연 → 검증 부족의 경우, 각 증상에 대응하는 것과 최초 원인을 통제하는 것의 효과를 비교한다. 단일 원인만 제거하면 모든 위험이 사라진다고 가정하지 않는다.

## 중요도 판단

| 요소 | 확인할 사항 |
| --- | --- |
| 가능성·근거 | 실제 관측·제약·경험이 있는가, 추정에 불과한가 |
| 영향·범위 | 사용자·데이터·안전·계약·운영에 미치는 피해 |
| 탐지 | 피해 전 식별할 수 있는가, 신뢰할 신호가 있는가 |
| 대응 시간·복구 | 대응할 시간과 실제 복구 수단이 있는가 |
| 대응 비용 | 구현·운영·검증·사용자 개입 비용과 부작용 |
| 잔여 위험 | 조치 후 남거나 새로 생기는 위험 |

근거 없는 확률이나 정밀 점수를 만들지 않는다. 불확실한 경우 정성적 판단과 그 한계를 설명한다. 가능성이 낮아도 피해가 크거나 되돌릴 수 없는 위험은 별도로 검토한다. 필수 계약과 안전성은 비용 절감만으로 포기할 수 없다.

## 대응 선택과 준비 상태

| 대응 | 적합한 상황 |
| --- | --- |
| 회피 | 위험을 만드는 선택이 필수적이지 않고 대안이 있음 |
| 예방 | 위험의 원인·조건을 사전에 통제 가능 |
| 완화 | 발생을 없애기 어렵지만 피해의 범위를 제한 가능 |
| 탐지 | 위반을 신뢰성 있게 확인하고 제때 대응 가능 |
| 복구 | 발생 후 정상 상태로 되돌리거나 재처리할 수 있음 |
| 수용 | 보호할 계약을 만족하면서 잔여 위험이 허용 가능하고 추가 대응의 이익이 낮음 |

한 대응을 항상 우선하지 않는다. 위험의 특성에 따라 여러 대응을 결합한다. 대응 비용과 해당 대응이 새로 유발할 위험도 검토한다. 위험 수용의 권한과 근거를 확인하며 사용자 침묵을 중요한 위험의 수용으로 해석하지 않는다.

대응의 존재와 준비 완료는 다르다. 어떤 신호에서 대응해야 하는지, 권한 있는 담당자와 필요한 도구·정보가 있는지, 피해 확대 전에 대응할 시간이 있는지, 실제 효과를 확인할 증거가 있는지 판단한다. 백업 파일이 있다는 사실은 복구가 검증됐다는 의미가 아니다. 완화·탐지가 예방을 보장하지 않는다.

## 종료와 재검토

중요한 위험과 대응, 잔여 위험 및 확인 한계를 설명할 수 있고 추가 분석이 선택을 바꿀 가능성이 낮으면 분석을 종료한다. 필수 계약 위반 위험이 해결되지 않거나 수용 권한이 없다면 영향을 받는 선택을 보류할 필요가 있는지 판단한다. 안전한 독립 작업까지 무조건 중단시키지 않는다.

새로운 증거, 계획·계약·환경 변경, 실제 실패 또는 대응책의 부작용이 기존 판단을 반박하면 영향을 받는 위험을 다시 평가한다.

## 경계와 반례

- 계획 승인이 있어도 데이터 유실 가능성이 새로 확인됐다면 위험의 영향과 대안을 재검토한다.
- 무제한 재시도로 지연을 줄이려다 서비스 부하와 중복 처리가 늘 수 있다. 원래 위험의 감소만으로 대응을 평가하지 않는다.
- 발생 빈도가 낮아도 복구 불가능한 삭제 오류는 중요한 위험일 수 있다.
- 복구 시험이 실행되지 않았다면 롤백 가능성을 확정하지 않는다.
- 작은 문구 수정에 대규모 위험 등록부를 만드는 것이 반드시 적합하지는 않다.

**책임 경계:** 현재 선택의 위험과 대응을 판단한다. 장기적 통제 수단의 필요성은 Preventive Engineering의 영역이며, 실제 작업 관리·승인·검증 절차는 대상 환경의 계약을 따른다. 다른 개인 원칙이나 Workflow를 반드시 호출할 필요는 없다.

**근거 수준:** 적절한 계획에도 발생할 수 있는 위험과 예방·대응의 필요성을 검토해 달라는 사용자 발언에서 도출한 후보 원칙이다. 상세 분류와 대응 기준은 그 의도를 보완하는 제안이며 사용자가 과거에 확정한 모든 철학이라는 뜻은 아니다.
