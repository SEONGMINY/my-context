# 개발 Workflow 실사용 평가

이 문서는 자동 테스트의 성공을 AI 행동 검증으로 오인하지 않도록 돕는 **수동 E2E 체크리스트**다.

1. 같은 커밋의 development-workflow를 Codex, Claude Code, Pi에 각각 설치한다. 해당 실행 파일이 없는 환경은 미검증으로 기록한다.
2. 새 세션에서 Skill 목록에 표시되는지 확인한다. 명시적으로 호출한 뒤 작은 수정/모호한 요구사항/복잡한 계획/결정 변경/인계를 각각 수행한다.
3. test/fixtures/workflow-scenarios.json의 각 request를 실제로 실행 가능한 테스트 프로젝트에 사용하고, expected와 forbidden을 실제 출력·행동·생성 파일로 평가한다. 문구가 포함되었다는 이유만으로 통과시키지 않는다.
4. 작은 수정에 대한 추가 문서 수, 질문 수, 시간·토큰(확인 가능한 경우), 재작업과 검증 누락을 기록한다. 제품 계약 우선과 개인 지식 조회 금지 조건을 특별히 확인한다.
5. 다른 에이전트가 이어받을 때는 원본 계약·커밋·검증 증거를 실제로 다시 열었는지 확인한다. 요약 문구만 맞는 것으로는 통과시키지 않는다.
6. 결과는 PASS/FAIL/NOT_RUN과 증거(사용한 실행 환경·버전, 출력·파일·커밋, 확인되지 않은 항목)로 기록한다. 모든 환경에서 동일한 동작을 가정하지 않는다.

자동 Node 테스트는 Skill의 설치·메타데이터·Fixture 구조만 검사한다. 사용자 의도 보존, 불필요한 작업 분해, 실제 에이전트 로딩 성공을 자동으로 입증하지 못한다.
