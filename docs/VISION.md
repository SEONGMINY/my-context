# my-context의 비전

개발 경험과 판단 기준을 한 프로젝트나 에이전트 대화 밖에서도 다시 쓸 수 있게 한다. 개발자가 자신의 원칙, 방법론, 작업 절차를 보존하면 다른 환경에서 일할 때도 같은 출발점을 가질 수 있다. 요구사항 분석, 도메인 분석과 스토리텔링, 테스트 원칙도 여기에 포함된다.

## 제품 경계

- **원본은 개발자가 소유한다.** 비공개 Git에 일반 Markdown과 관련 파일을 보관한다. 검색 인덱스와 배포 번들은 원본에서 다시 만든다.
- **MCP는 조회 진입점이다.** 요청에 필요한 지식과 절차, 첨부 파일을 가져온다. 현재 원격 연결은 Cloudflare Worker가 제공한다. 조회 인터페이스를 교체해도 지식 원본은 계속 쓸 수 있다.
- **실행과 판단은 프로젝트가 맡는다.** 공통 Skill은 여러 프로젝트에서 쓰는 절차의 원본이다. 제품별 요구사항, 도메인 계약, 테스트, 실행 환경과 검증 기준은 해당 프로젝트가 소유한다.
- **지식 변경은 사용자가 통제한다.** 사용자가 요청한 범위에서 조회하고, 변경은 원본과의 충돌을 확인한 뒤 승인된 범위에서 반영한다.

## 성공 기준

다른 프로젝트나 노트북에서도 필요한 자산을 찾아 출처와 적용 범위를 확인할 수 있다. 공통 절차는 한 곳에서 관리하고 여러 프로젝트에서 재사용한다. 자산이 늘어도 조회와 검토에 드는 비용이 과도하게 증가하지 않는다.
