# my-context의 비전

my-context는 개발 경험과 판단 기준을 여러 프로젝트와 환경에서 재사용할 수 있게 한다. 개발자는 자신의 원칙, 방법론, 작업 절차를 보관한다. 이 자산에는 요구사항 분석, 도메인 분석, 도메인 스토리텔링, 테스트 원칙이 포함된다.

## 제품 경계

- **개발자가 원본을 소유한다.** 개발자는 Markdown 원본과 첨부 파일을 Git 저장소에 보관한다. 빌드는 원본에서 검색 인덱스와 배포 번들을 만든다.
- **MCP는 조회를 제공한다.** Cloudflare Worker가 현재 원격 MCP를 제공한다. 조회 방식이 바뀌어도 개발자는 같은 원본을 쓸 수 있다.
- **각 프로젝트가 실행과 판단을 맡는다.** 개인 원칙·Playbook은 특정 Skill에 종속되지 않고 관련 요청에서 선택적으로 활용된다. 공통 Skill은 여러 프로젝트에서 쓰는 작업 절차를 담는다. 프로젝트별 요구사항, 도메인 계약, 테스트, 실행 환경과 검증 기준은 해당 프로젝트에 둔다.
- **사용자가 지식 활용과 변경을 통제한다.** 자산 조회는 명시적 요청 또는 사용자가 활성화한 선택적 정책에 한정한다. 원본과 충돌하는지 확인하고 승인한 범위에서만 지식을 변경한다. 원격 MCP의 인증은 서버 접근을 제한하며, 자산 사용 동의와 관련성은 에이전트 행동 정책에서 판단한다.

## 성공 기준

사용자는 다른 프로젝트와 환경에서 필요한 자산을 찾을 수 있다. 각 자산의 출처와 적용 범위를 확인할 수 있다. 개발자는 공통 절차를 한 곳에서 관리한다. 자산이 늘어도 조회와 검토에 드는 비용을 관리할 수 있다.
