# my-context의 사용자 문제

이 문서는 개인 개발자 한 명이 프로젝트를 설계하고 사용하면서 한 말을 기록한다. 문제의 빈도와 다른 사용자의 경험은 확인하지 않았다.

## 현재 제품과의 연결

아래 발언은 문제를 발견한 근거이며 발생 빈도나 개선 효과를 입증하는 측정값은 아니다. 대응 방향은 [VISION](VISION.md)의 원본 소유·선택적 조회·프로젝트 실행 경계 및 [개발 Workflow](../skills/development-workflow/SKILL.md)의 요구 확인·인계·검증 원칙에 연결된다. 실제 효과는 [실사용 E2E](../test/workflow-evaluation.md)와 프로젝트별 결과로 별도 확인한다.

## 작업이 요구사항에서 벗어난다

> “뭔가 지금 너무 갔는데? 내 요구사항 다시 이해해볼래?”

> “왜 지금 계속 요구사항을 이탈하나요? 무엇떄문인가요? 이것을 개선하고 싶습니다.”

## 이전에 정한 구조와 판단 기준을 확인하기 어렵다

> “이전에 말한건 유효해? product -> mcp -> my-context 방향으로 가는건?”

> “다시 한번 현재 요구사항을 이해하고, 현재의 문제가 무엇이며, 어떻게 해결할지 파악해주세요.”

## 구조가 복잡해지면 시간과 비용이 늘고 정확도가 낮아질 수 있다

> “여기서 이 방법외에 시간과 토큰을 줄일 수 있는 더 좋은 방법이나 방법론은 없을까?”

## 사용 방법과 조회 결과를 이해하기 어렵다

> “사용방법 쉽게 알려줘.”

> “실제 조회되는 걸로 설명해줘.”

## 한 시스템에서 관리할 자산의 범위가 불분명하다

> “`my-context`를 개인 개발 지식에서 출발해, 앞으로 Skill과 개발 하네스까지 필요에 따라 관리할 수 있는 개인 개발 자산 시스템으로 발전시킬지 검토진행해주세요.”

## 다른 환경에서 같은 지식과 작업 절차가 필요하다

> “지금 나의 환경은 이 노트북외에도 다른 노트북 또 다른 환경에서 작업할 수 있어”

> “그러면 매번 노트북에서 skill 다운 받아야 하지 않아?”
