# Problem statements — my-context

개인 개발자 한 명이 프로젝트 설계와 사용 과정에서 표현한 문제를 기록한다. 별도 고객 인터뷰로 문제의 빈도나 다른 사용자의 경험을 확인한 기록은 없다.

## 1. 개발 작업에서 중요한 맥락과 요구사항이 벗어난다

> “뭔가 지금 너무 갔는데? 내 요구사항 다시 이해해볼래?”

> “왜 지금 계속 요구사항을 이탈하나요? 무엇떄문인가요? 이것을 개선하고 싶습니다.”

## 2. 내가 정한 구조와 판단 기준이 이어지는지 확신하기 어렵다

> “이전에 말한건 유효해? product -> mcp -> my-context 방향으로 가는건?”

> “다시 한번 현재 요구사항을 이해하고, 현재의 문제가 무엇이며, 어떻게 해결할지 파악해주세요.”

## 3. 구조가 커지면서 시간·토큰·정확성·유지보수 비용이 걱정된다

> “여기서 이 방법외에 시간과 토큰을 줄일 수 있는 더 좋은 방법이나 방법론은 없을까?”

> “더 넓은시야에서, 더 다양한 관점에서 확인해줘.”

## 4. 시스템을 실제로 어떻게 사용하는지, 무엇이 조회됐는지 이해하기 어렵다

> “사용방법 쉽게 알려줘.”

> “실제 조회되는 걸로 설명해줘.”

## 5. 지식과 재사용 절차가 어디까지 같은 시스템에 속해야 하는지 고민된다

> “`my-context`를 개인 개발 지식에서 출발해, 앞으로 Skill과 개발 하네스까지 필요에 따라 관리할 수 있는 개인 개발 자산 시스템으로 발전시킬지 검토진행해주세요.”

## 6. 다른 노트북에서 같은 지식과 작업 절차를 사용하고 싶다

> “지금 나의 환경은 이 노트북외에도 다른 노트북 또 다른 환경에서 작업할 수 있어”

> “그러면 매번 노트북에서 skill 다운 받아야 하지 않아?”
